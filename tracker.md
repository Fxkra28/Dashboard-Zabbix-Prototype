# Tracker: what to fix, improve and add in the HCML portals

This is a list of everything worth changing in the two HCML monitoring portals, `hcml-portal` and
`hcml-portal-ollama`. It covers security, the backend, the frontend, UI and UX, and the integrations
that connect them. Each item says what is wrong, where it is in the code, and what to do about it.

This is the list to fix from. Each item's row says whether it has been fixed, and
[Where things stand](#where-things-stand) summarises the state on 7 October.

  reading the body, returns typed errors, and keeps the Zabbix address out of responses (`zabbix.ts`).

## Terms used here

Terms such as BFF, JWT, SSE, SLA, SLI, Zabbix, token and CI are in the [README glossary](README.md#glossary).
These are the new ones.

| Term | What it means here |
|---|---|
| Acknowledge, Close | The two Zabbix actions the portal can take on a problem. Acknowledge marks it as seen, optionally with a message. Close asks Zabbix to resolve it, which the Zabbix server applies a few seconds later |
| aria-live, `role="status"`, `role="alert"` | Markers that make a screen reader read out a change without the user moving to it |
| axe | An automated accessibility checker that runs in the browser or in tests |
| Backoff with jitter | Waiting longer after each failed retry (2 s, 4 s, 8 s), plus a small random extra, so many screens do not all retry at the same moment |
| bcrypt | A slow, salted way to store passwords, so a leaked file does not reveal them |
| Clickjacking | Another website loading the portal invisibly in a frame and tricking a user into clicking a button, such as Acknowledge |
| Cold call, warm call | A request answered by doing the work (cold) against one answered from the cache (warm) |
| CORS | The browser rule that decides which other websites may call an API |
| CSP (Content-Security-Policy) | A header that tells the browser which scripts, styles and connections a page may use, which limits the damage of an injected script |
| CSRF | A trick where another website makes the user's browser send a request that the browser signs automatically, which matters once cookies are used |
| DNS rebinding | A web page that switches its own domain name to point at 127.0.0.1, so the browser treats a local service as part of that page |
| "Display OK triggers for" | A Zabbix setting: how long a resolved problem keeps appearing in "recent" problem lists |
| End of life (EOL) | The date after which a runtime, such as Node 20, gets no more security fixes |
| Formula injection | A CSV cell starting with `=`, `+`, `-` or `@` that a spreadsheet runs as a formula when the file is opened |
| gzip | Compression that nginx can apply to files before sending them, usually shrinking scripts to about a third |
| Healthcheck, readiness check | A healthcheck asks "is the process alive". A readiness check asks "can it do its job", for example whether Zabbix answers |
| HSTS (`Strict-Transport-Security`) | A header that tells a browser to use only HTTPS for this site from now on. A browser ignores it when it arrives over plain HTTP |
| httpOnly cookie | A cookie that page scripts cannot read, so an injected script cannot steal the token inside it |
| Kiosk or wall mode | A full-screen view designed to be read from across a room, with no sign-in interruptions |
| Landmark, skip link | Landmarks such as `<main>` let screen-reader users jump to parts of a page. A skip link lets keyboard users jump past the menu |
| LRU | Least recently used: when the cache is full, the entry nobody has asked for the longest is dropped first |
| Major version | A version change (Fastify 4 to 5) that may break existing code, so it needs planning and testing |
| Negative control | A check run first on something built to fail it, to prove the check can fail. A contrast check that passes everything is worthless |
| `no-store` | The `Cache-Control` value that tells a browser and any proxy not to keep a reply |
| Open redirect | A sign-in link that can be made to send the user to another website after login |
| Parity check | The diff that confirms the two copies differ only in the 21 intended files |
| Percent-encoding | Writing a character in a URL as `%` plus its code: `%61` is `a`, so `/%61pi/` means `/api/` |
| Pinned cache entry | A cache entry that is evicted only after every unpinned one, so a report that costs seconds to rebuild, such as a closed month's SLA, survives a flood of cheap keys |
| PID 1, SIGTERM | SIGTERM is the polite "please stop" signal Docker sends. The first process in a container (PID 1) ignores it unless the code handles it |
| Prompt injection | Text inside the data given to an AI model that tries to act like an instruction to the model |
| Rate limit | A cap on how many requests one client may send per minute |
| Resolved problem, `r_eventid` | Zabbix links a problem to its recovery event. An `r_eventid` other than `0` means the problem has already resolved |
| Soft 404 | A server that answers 200 with the home page for a path that does not exist, so a scanner reads every guess as found |
| Stale-if-error | A cache rule: when a fresh fetch fails, answer with the last value kept, however old |
| Super admin | The Zabbix role that may call every API method and change everything. The portal's two tokens belong to one |
| Suppressed problem | A problem raised while its host is in a Zabbix maintenance window |
| WCAG, contrast ratio, target size | The web accessibility standard. Normal text needs 4.5:1 against its background; large text, focus rings and control edges need 3:1. A button or link should measure at least 24 by 24 CSS px (WCAG 2.2, criterion 2.5.8), unless spacing keeps it apart from its neighbours |
| X-Data-Stale, X-Data-Age-Seconds | Two response headers that say an answer is an old copy kept because Zabbix failed, and how old it is, in seconds. Absent on a live answer |
| X-Forwarded-For | A header in which proxies record the original client's address. If it is trusted blindly, a client can claim any address |
| XSS | Cross-site scripting: someone else's script running inside the portal page |

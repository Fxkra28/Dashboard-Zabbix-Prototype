## The large files, taken apart (ST-07, ST-08)

The 16 October step moved files and left the large ones whole. They were split by the same method, the TypeScript compiler's API, so that every declaration keeps its own text, and each was compared with its original token for token (the `export` keyword and the comments aside). The comparison was shown to fail on a change of one token.

| `web/src/types.ts` (862 lines) | `web/src/types/`, a file for each feature behind an `index.ts` |
| `web/src/guards.ts` (792 lines) | `web/src/guards/`, the same, with `shape.ts` for the shared checks and `misfit.ts` for what a page says when one fails |

No page and no test changed an import: each `index.ts` re-exports the same names, so `import { api } from '../../api'` and `vi.mock('../../api')` still resolve to the same module. The three folders stay at the root and not inside the features, because the root may import no feature and a page of any feature calls any of them. The server's pieces stay flat in `services/`: the layering test sees only the files directly in a folder, so a nested folder would have weakened it.

Two rules came with it, one on each side. No import cycle among the files of `services/`, and none among the web's shipped files (a type-only import does not count), and no piece of the assistant imports its entry file, which tests replace. Each was broken once to see it fail, and the first version of the web rule let a cycle through `api/index` pass, which that breakage showed. There are 11 layering tests on the server and 7 on the web now.
